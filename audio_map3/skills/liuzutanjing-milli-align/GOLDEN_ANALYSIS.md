## 4. 規則 C：壇經不採用「短收尾可一律吞入下段」的寬鬆版

人工後移的 L2 [59] +1.441、[60] +1.921、[62] +0.896、[67] +1.503，以及 L3 [29] +0.830、[82] +1.572，都提示：
- hosting gap 若切在前段語義收尾中，應退 **contact＝前段末內容字 END**；
- 不可因收尾只有幾字就預設可吞；先檢查它是否仍是前段完整句子的一部分；
- 只有「未印出的過場且確屬本段」才可納入下段 lead-in，且 note 必須寫明文字證據。

因此通用 milli-align 的短收尾例外，在壇經要改為 **先否決、再逐例證明**，不能自動吸收。

## 5. 規則 D：公式只負責取位，不能救錯 own_first

- 保留現行 gap 取位作為候選：`.374 / .560 / .650 / .780`。
- 但人工差異主要不是係數錯，而是 **own_first 選錯或前段收尾被吞**；先修語義歸屬，再算 gap。
- L3 多筆 ±0.1／±0.2s 是局部人工微調，**不得寫成全域 ±0.2 規則**。
- contact 必須用字級 `t_end_of()` 精確 END，不能用 onset、行內插值或任意「−0.2s」。

## 6. zero、head-zero 與鏈

- `zero:false` 是 zero→READ 的必要顯式旗標；只改 start 不足以恢復實寬。
- zero 錨取鏈後「前個 READ end」；有前一個 READ 時不可自行錨到下一個較晚內容字。
- 講首在首個 READ 之前的未念整章塊，head-zero 正典為 **0.000**；有前一個 READ 的 zero 不可套 0.000。
- 不得為了修鏈改動 confirmed zero 或 confirmed 段。若 golden 擋路，先重審 zero 是否其實應 READ，而不是強行壓住下一段。

## 7. 不能直接泛化的項目

- 單段 ±0.1／±0.2 微調、單次人工選點差異，不能變成固定偏移。
- `method=ngram` 是人工 UI 存回格式，不是證據強度或對齊方法證明。
- span_ok／skip_ok 總數會因 zero→READ 而下降；短經文插講段被標 unknown／bad 不等於鏈錯，必須逐段解釋，不能為追求比例把 READ 改回 zero。
- 人工兩期都全 confirmed 後即成 golden；後續任何重建、重套、重跑對齊器都不得變更其 `start/end/conf/confirmed/zero/reviewed`。
