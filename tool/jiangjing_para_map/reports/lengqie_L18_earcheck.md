## 三、本輪修掉一個 `milli_refine` 的真 bug（重要）

裁決表同時改**相鄰兩段**且後段 start 後移時（[48] 703.65 與 [49] 711.00），舊版
`milli_refine` 產生**負長度 span** `703.65–703.00`。根因：

```python
reads = [i for i, p in enumerate(paras) if p["end"] > p["start"] or ...]   # ← 事後判定
```

先套的 [48] 端點被夾到自己的 start 之下 → `end > start` 為 False → **[48] 被踢出 READ 集合**
→ 鏈 pass 永遠接不上，且**靜靜寫進 SoT**。

已修（`milli_refine.py`）：
1. **READ 身分改為「變更前」記錄**（`reads_before`），判準＝「無 `zero` 標記 且 起訖不等」，
   含已損壞的負長度段 → 本程式能自我修復。
2. **安全網**：鏈 pass 後若仍有負長度／破口，**abort 不寫檔**並印出段號。

本檔已驗證：修正後重跑同一張表 → 修好 [48]=`703.65–711.00`，再跑第二次＝0 段變更（idempotent）。
