## 四、⚠ 本輪抓到的一個 idempotence 陷阱（已寫入 SKILL）

把 [34] 設為 zero 時，錨點寫成原 span 的 `591.04` → **每次套用都被鏈 pass 覆寫成 591.10**，
`milli_refine --apply` 變成**非 idempotent**（連跑三次都在動）。

**原因**：zero 錨點依慣例＝**前一 READ 段的 end**（＝**下一** READ 段的 start）。
鏈 pass 把 [33].end 設成 [35].start = 591.10，再把 zero 錨回 [33].end = 591.10。

**規則**：裁決表裡 `zero: true` 的 `start` **必須寫成「鏈後的值」（＝下一 READ 段的 start）**，
不能寫原 span 的任意值。本表 [34] 已改為 591.10，連跑三次皆 0 段變更。
